# 写作与发布碎片

碎片存放在 `content/fragment/`，使用简短、稳定的语义文件名，例如 `mnist-format.md`。标题可以修改；文件名决定 URL，改名后必须同步更新引用。

使用 `Templates/new-fragment.md` 新建。默认 `draft: true`，开发环境可预览，生产构建不会发布。写好后改为 `draft: false`，将 `date` 设为首次公开当天；不填写 draft 的旧文件仍视为已发布。公开碎片可经搜索和链接访问，不出现在首页、导航、文章归档或 RSS。

`date` 和 `updated` 使用 `YYYY-MM-DD`（建议用引号）。`updated` 没有实质更新时留空；只有核心观点、解释、重要例子或依据改变时才更新，错字和排版不必修改。更新时间不能早于首次公开日期。缺少标题或日期的草稿暂不预览，补齐后即可；未来发布日期保持隐藏。

## 引用规则

所有文章和碎片采用同一规则，目标是文件名而不是页面标题：

| 写法 | 含义 |
| --- | --- |
| `[[文章文件名]]`、`[[posts/文章文件名]]` | 引用文章 |
| `[[fragment/碎片文件名]]` | 引用碎片 |
| `[[fragment/mnist-format\|其数据格式]]` | 保留目标，指定显示文字 |
| `[[fragment/mnist-format#^stable-id]]` | 引用目标段落末尾的 `^stable-id` |
| `[[#^stable-id]]`、`[[^stable-id]]` | 当前页面的块 |
| `[[#实际标题ID]]` | 当前页面的标题锚点 |

同名文章和碎片靠前缀区分，不自动猜测。标题锚点采用网页实际生成的 ID，可从目录链接获取。正文中的教程示例请放在行内代码或代码块里。

生产构建检查未发布/不存在的内容、缺失锚点和重复块 ID，失败会指出源文件及修复建议。先发布被引用内容，或移除尚未生效的链接；不要靠开发预览中草稿可见来判断线上可用性。
