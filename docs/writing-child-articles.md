# 撰写子文章

子文章用于自己归纳、总结和压缩一篇文章的内容，也可以继续挂载更深一层的文章。使用 `Templates/new-child-post.md`，仍保存为 `content/posts/` 下的 Markdown 文件。

## 绑定父文章

```yaml
title: 用三句话解释反向传播
date: "2026-11-05"
description: 从计算图和链式法则理解反向传播
parent: "post:2026-10-18-001"
draft: true
```

将 `parent` 填为 `post:` 加父文章文件名（不含 `.md`），不是文章标题、网址或 wiki 链接。父文章不用维护子文章清单。发布时填写实际发布日期，确认所有祖先已发布，再将 `draft` 改为 `false`。

例如 A 是原文，B 的 parent 为 `post:A`，C 的 parent 为 `post:B`，便形成三层关系。每篇只能有一个直属父文章，不能自引用或形成循环。列表按子文章发布日期从早到晚排列，同日按文件名稳定排序。

## 阅读入口

父文章顶部的修订历史下面有“子文章 · N 篇”，默认折叠，展开后只有直接子文章的标题链接。没有修订历史也能展示子文章列表；没有子文章则隐藏。子文章顶部提供返回直属父文章的链接。历史比较只影响正文，不会改变当前的父子关系。

子文章有独立正文、链接、目录和修订历史，可以直接分享和站内搜索；搜索显示“提炼自：父文章标题”。它不出现在首页、分类、归档、系列、标签汇总、RSS、相关推荐或全局上下篇中，不设置或继承分类和系列。普通文章模板遗留的 `category`、`series`、`seriesIndex` 会被忽略。标签和日期独立填写，不继承父文章。子文章页标签仅展示为文字，不链接到全站标签汇总页。

## 与碎片知识的区别

子文章始终是 `post`，地址为 `/blog/<文件名>/`。碎片仍在 `content/fragment/`，类型为 `fragment`，地址为 `/fragment/<文件名>/`。碎片不支持 `parent`，不能充当父文章或子文章。

正文仍可通过 `[[posts/文章文件名]]`、`[[fragment/碎片文件名]]` 或块链接互相引用；这些链接与反向引用都不会自动建立父子关系。同名文章和碎片通过 `post:` / `fragment:` 区分，绑定只允许前者。

## 修改归属与诊断

- 改 parent 即可转移归属；移除 parent 或留空会使文章恢复为顶层文章，进入相应全站列表。
- 改文章标题不影响绑定；改文件名要同步修改指向该文件的 parent 和正文引用。
- 删除父文章前，先处理其子文章的归属。
- 公开子文章的祖先必须全部公开；绑定草稿、未来文章、缺失文章、自身、碎片或循环会阻止生产构建，并指出源文件和 parent 字段。
- 开发模式允许有效草稿树预览；无效关系及其后代会告警并排除预览，不会被当作顶层文章展示。

模板的 parent 默认留空，发布前务必填写；留空本身表示普通顶层文章，不代表私密或草稿。
