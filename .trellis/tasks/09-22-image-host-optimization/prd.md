# 图床优化：保持 PicGo 写作流程

## 目标与本轮交付

零新增日常操作、零新增持续费用，减少图片加载等待，改善失败恢复，保持截图清晰度。本轮交付 PicGo 自定义规则、连接预热、正文/灯箱失败重试和运行时契约更新。

## 硬约束

- 流程固定：图片到剪贴板 → PicGo 上传 → 复制 Markdown URL → 粘贴到笔记。
- 保留 GitHub + jsDelivr、唯一文件名和 @main 链接，不要求手工维护 commit hash、压缩、分类图片或补尺寸。
- 不新增收费服务、在线压缩账户或运行时后端；文章图片编译保持同步、零网络。
- 默认无损，不缩放、不裁剪、不全量转换格式；旧 Markdown、历史版本、图片链接持续有效。
- 不覆盖/删除远端原图，不改动当前其他未提交工作。

## 已确认事实

- 正文已有 200px 提前量的懒加载；首屏图片也等待客户端初始化。
- 背景为桌面三张及移动端一张；HTML 暂无连接预热。
- 本机 squeeze 虽有自定义规则，实际模式仍是 local，未启用“只压缩 >=300KB PNG”的规则。之前对话的完成声明有误。
- 单次且可能经代理的网络采样不足以确定大陆直连瓶颈，不作为性能承诺。

## 验收标准

- [ ] 沿用同一剪贴板上传入口与 Markdown 复制方式，无额外快捷键或处理步骤。
- [ ] PNG >=300KB 本地无损压缩；其他图片原样通过；失败或变大返回原图。
- [ ] 代表性截图解码后像素和尺寸一致，不仅凭肉眼判断无损；特殊图像无法保真则原样通过。
- [ ] 静态页面获得唯一 CDN 连接提示，不提前下载整篇图片或全部背景。
- [ ] 图片失败后可明确重试；无无限请求、随机镜像切换或时间戳缓存绕过。
- [ ] 切换主题不把错误态改回 loading；灯箱、历史比较、移动端和 hash 定位无回归。
- [ ] 区分压缩耗时、字节量、网络等待、图片出现时间，按同条件基线验证，不承诺统一提速比例。
- [ ] 配置与代码有分项回退方式，正常构建不增加图片网络探测。

## 首期范围外

对象存储迁移、多图床同步、全量 WebP/AVIF、构建期镜像所有图片、Service Worker、自动 commit URL 改写、RSS 改造。背景衍生资源与首屏加载策略仅在后续测量通过后另行纳入。

## 待定事项

首期无阻塞性产品问题：流程、费用、质量约束已由对话明确。进入实施由用户后续指令决定。
