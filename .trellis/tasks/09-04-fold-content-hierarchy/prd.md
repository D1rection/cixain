# 重构题目描述块内部层级与代码样式

## Goal

让算法题帖的“题目描述”折叠块拥有清晰、稳定的内部视觉层级，并让其中的代码示例复用博客既有代码视觉语言；折叠块内部层级不得进入文章目录（TOC）或干扰目录激活状态。

## Requirements

- 保留 `> [!fold]` 作为题目描述块的唯一写作入口，兼容 Obsidian 与现有构建流程。
- 在折叠块内支持两级视觉层级：
  - 一级：输入格式、输出格式、样例、数据范围、提示等主要分段。
  - 二级：输入、输出、解释等样例内分段。
- 内部层级在生成页面中保留可访问的 heading 语义，但不得输出为真实 `h2`–`h6`，不得被现有 TOC 提取逻辑收集。
- 新写法应允许作者在 Markdown 中使用正常标题表达层级；既有以独立粗体段落表示标题的题干仍需兼容。
- 题干普通文本不再整体使用过小、过淡的次级样式，需与博客正文保持可读性一致，同时维持折叠块的次级内容定位。
- 无语言标记的题目输入、输出和集合示例代码块应复用博客现有 Everforest 深色代码视觉，包括字体、圆角和复制交互。
- 题干代码块不显示行号；移动端需缩小内边距、保留横向滚动能力，并让复制入口可发现。
- 不改变文章外部真实标题、TOC、普通代码块、普通 callout 或题目信息栏的现有行为。
- 更新题解模板与当前 `2026-09-04-001` 文章，使内容源明确表达新的内部层级。

## Acceptance Criteria

- [x] `details.fold` 的生成 HTML 中不存在 `h2`–`h6`，内部层级使用非原生标题元素表达，并带有正确的 `role="heading"` / `aria-level`。
- [x] 当前文章的 TOC 只包含折叠块外的文章标题；“输入格式”“输出格式”“样例”“数据范围”“提示”等不进入 TOC。
- [x] 折叠块内一级、二级标题和普通正文在亮色、暗色主题下均能清晰区分。
- [x] 题干中的普通 fenced code 在亮色、暗色主题下均与博客现有代码块风格一致，且不显示行号。
- [x] 390px 窄屏下折叠块、公式和代码块不撑破页面；长输入仍可横向查看，复制按钮可见或可明确发现。
- [x] 既有粗体标题写法仍可获得对应层级样式，其他普通粗体段落不被误判。
- [x] 构建通过，并通过桌面端与 390px 窄屏视觉复核。
