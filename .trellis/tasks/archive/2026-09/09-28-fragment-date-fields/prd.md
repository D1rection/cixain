# 规范碎片模板的发布日期与更新时间

## Goal

在碎片模板中说明发布日期和更新时间的含义，避免把草稿创建时间、首次公开时间和后续内容更新混为一谈。

## Requirements

- `date` 保持必填，语义为首次公开日期；若碎片曾以草稿形式保存，应在首次发布时将其调整为实际公开日期。
- 模板增加可选的 `updated` 字段，使用 `YYYY-MM-DD`；无实质更新时留空。
- 仅在核心观点、解释、重要例子或依据发生实质变化时填写 `updated`；错字、排版和纯链接修复不触发更新时间。
- 不增加单独的 `created` 字段，不改构建逻辑和页面展示逻辑。
- 正文提示说明日期字段是维护元数据，不要求碎片内容采用固定章节结构。
- 在 frontend content-pipeline spec 中记录碎片日期字段约定，避免模板规范只存在于模板注释中。

## Acceptance Criteria

- [x] `Templates/new-fragment.md` 清楚标明 `date` 是首次公开日期、`updated` 是可选的实质更新时间。
- [x] `updated` 留空与填写日期均能被 frontmatter 正确解析；现有更新日期展示与排序逻辑未修改。
- [x] 模板说明发布日期在草稿首次公开时确定，且哪些内容变更需要更新 `updated`。
- [x] content-pipeline spec 与模板保持一致；未改站点行为。
