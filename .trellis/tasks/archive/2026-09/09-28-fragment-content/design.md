# 设计：独立存储，共享编译和引用解析

## 内容与身份
新增 `content/fragment/*.md`，公开 URL 为 `/fragment/<encoded-slug>/`，不生成 `/fragment/` 列表。维持现有文章 `/blog/<slug>/`。
内部 ID 使用 `post:<slug>` / `fragment:<slug>`，不可仅用 slug 标识。构建注册表记录 `{id, kind, slug, title, url, sourcePath, bodyPath, date, updated, description, tags}`。URL 集中生成并遵循尾斜杠和 BASE_URL 约定，禁止消费者各自拼接 `/blog/`。

碎片必需 title/date，选填 updated/tags/description/draft；slug 来自稳定文件名；默认摘要取正文可读文本，不包含公式的重复渲染文本、按钮或隐藏标记。沿用北京时间日期及生产发布过滤规则。kind 由目录确定，不让 frontmatter 覆盖。源码先限平铺；标签仅作为知识标记和搜索字段，不链接到只含文章的旧标签列表。

保留 posts.json 的文章集合语义；新增 fragment/fragments.json 和供构建使用的公共注册表。注册表只含元信息，正文按页注入/加载。不把所有内容塞回 posts，以免改变归档、RSS、分类计数和系列。

## 链接与引用图
两遍构建：先发现内容并决定环境可见集合，再编译正文及收集引用，最后生成反向链接与诊断。所有可见性判断共享同一规则。

- `[[fragment/name]]` 显式引用碎片；`[[posts/name]]` 显式引用文章。
- `[[name]]` 保持旧契约，只解析文章，避免未来同名改变语义。
- `[[fragment/name|显示文字]]` 自定义文本，无别名使用目标标题。
- `[[fragment/name#^block]]` 和同页 `[[^block]]` / `[[#^block]]` 解析到稳定块锚点。
- 普通标题锚点与目录共享同一生成函数；修改标题可能改变该锚点，长期引用推荐 ^id。
- 标准 Markdown 站内链接也进入引用图；只识别本站规范文章/碎片 URL，不收集图片资源和任意外链。

统一引用边 `{sourceId, targetId, anchor?}`，按来源页面去重用于页面底部“被引用于”。无效链接报告来源文件、目标及原因；延续现有警告策略，重复内容身份/不安全路径直接失败。生产中指向草稿的链接不从草稿元信息补标题；作者显式写出的文字保留，但不得自动注入隐藏内容。历史编译复用解析器，保持 compileMD 调用兼容，历史正文不反向写入当前引用图。

## 页面和数据加载
新增轻量 Fragment 页面，抽取共享正文阅读组件，保留文章特有的题目信息、系列、版本对比和文末模块。碎片展示标题、日期/更新日期、正文及反向链接；长文目录复用，短内容不占目录空间。

SSG 注入自身正文和本页引用来源摘要；不内联其他正文或全站引用图。开发入口加载两类元数据。跨类型标准链接优先使用规范 href 完整页面导航，使任意来源都能拿到目标 SSG 数据；现有搜索跳转需同步适配，不能在原页面精简 Context 中找不到目标后显示错文。未来若保留 SPA 跳转，须实现按目标页面加载静态数据、取消请求及身份校验，不能只加 Route。

静态输出新增 fragment 路由与正文资源，生产复制只消费当前发布清单，不复制目录中残留的旧/草稿 HTML。无 JS 的正文和锚点也应可读。分享先用默认 OG 图，不新增逐碎片绘图成本；sitemap 收录公开碎片，RSS 保持文章策略。
