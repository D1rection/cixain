# 支持 Obsidian 原始标题链接

## Goal

作者继续使用 `[[文件名#标题|显示文字]]` 和 `[[#标题]]` 写作；网站自动定位对应章节，不要求作者手动计算网页 ID。修复链接生成与发布校验的语义差异。

## Background

2026-10-01 的部署在内容编译阶段失败。`[[2026-08-21-001#3.3 Softmax 回归]]` 与 `[[2026-08-12-001#1. 梯度下降法]]` 的目标标题实际存在，但分别生成 ID `33-softmax-回归`、`1-梯度下降法`。当前构建器直接拿原始标题与 ID 比较，也把原始标题直接写入 href。

## Requirements

1. 支持跨文章、跨碎片和同文的 wiki 标题链接，保持既有文件名、类型前缀、别名与百分号编解码规则。
2. 标题解析必须绑定目标页面最终实际 ID；支持带空格、大小写、标点、中文、行内格式、公式，以及已有块 ID 的标题。
3. 不改变既有标题 ID 生成规则；已有实际 ID 链接在无语义冲突时继续有效。`#^id` / `^id` 仍是块引用，普通 Markdown URL 仍按实际 hash 校验。
4. 相同原始标题默认取正文中第一个可定位标题；不同标题即使生成相同 slug，也能分别定位。标题匹配与旧 ID 匹配指向不同元素时明确诊断，避免静默跳错。
5. 生成链接与校验消费同一解析结果；缺失标题、块或目标，以及未发布目标仍触发现有生产门禁。错误保留作者写法、源文件与位置。
6. 解析不受文件遍历顺序影响，支持前向引用和循环引用。不得因被引用而发布草稿或未来内容。
7. 搜索、目录、反向链接与历史版本编译继续兼容；历史中的 wiki 链接指向当前可访问内容，不承诺还原整站历史快照。
8. 不为标题解析引入浏览器全站映射请求或新运行时依赖，不重复执行全站 Shiki/KaTeX 编译。

## Non-goals

完整复刻 Obsidian 的文件寻址、嵌入、跨库搜索、多级 `#父标题#子标题` 路径；扩展 h1 或折叠题干小标题的锚点规则；重新生成现有标题 ID；修改文章写法、部署命令或历史版本阅读器的交互。

## Acceptance Criteria
