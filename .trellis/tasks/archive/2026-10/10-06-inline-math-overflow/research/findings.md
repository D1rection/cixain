# 行内数学内容撑出引用块：复现与方案评估

日期：2026-10-06。当前交付为复现和方案分析，未实施正式修复。

## 复现步骤

1. 使用已经运行的 Vite 开发站点，访问 `http://localhost:5173/blog/draft-ml/`。
2. 进入第三节 `3. LMS with the kernel trick`，找到 “我们可以通过归纳法证明如下” 后的引用块。

## 尺寸证据

单位 px，client/scroll 为 DOM 的整数尺寸，公式宽度取整。

| 场景 | 引用块 clientWidth | 引用块 scrollWidth | 目标段落 clientWidth | 目标段落 scrollWidth | 目标公式宽度 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 原始，1440 深色 | 644 | 845 | 604 | 825 | 825 |
| 原始，375 深色/浅色 | 307 | 845 | 267 | 825 | 825 |
| 段落滚动，1440 深色 | 644 | 644 | 604 | 825 | 825 |
| 段落滚动，375 深色 | 307 | 307 | 267 | 825 | 825 |
| 拆出文字，1440 深色 | 644 | 644 | 604 | 604 | 10、159 |
| 拆出文字，375 深色/浅色 | 307 | 307 | 267 | 267 | 10、159 |

375px 下第二个独立公式的 clientWidth/scrollWidth 为 267/417，保持现有局部滚动；引用块自身不再溢出。

## 根因与边界

- `content/posts/draft-ml.md:69`、`:71`、`:75` 将英文说明整段包在 `$...$` 中。第 75 行长句最终生成一个约 825px 的 `.katex-html > .base`。
- 当前安装的 KaTeX 样式 `node_modules/katex/dist/katex.css:177` 为 `.base` 设置 `display: inline-block; white-space: nowrap; width: min-content`。内部文字空格也并非普通段落的断行机会。
- `src/components/PostContent.module.css:8` 已设置 `overflow-wrap: anywhere`，但不能拆开上述原子式的内部行盒。
- `src/components/PostContent.module.css:389` 的 `.katex-display` 有局部滚动；单美元渲染的行内公式不命中它。
- `src/components/ScrollContainer.module.css:8` 的主区域横向隐藏放大了窄屏后果，但改变主容器只会让页面横向溢出，不解决内容布局。
- 引用块的固定正文宽度不是根因。深浅主题尺寸一致，问题来自内容写法与行内数学溢出策略。

KaTeX 官方说明：行内公式的自动断行点主要是最外层关系符/二元运算符；独立公式默认不自动断行。这不等同于自然语言按词换行。来源：<https://katex.org/docs/options>、<https://katex.org/docs/supported>。项目安装版本为 0.17.0，以本地 CSS 和实际 DOM 为此次验证依据。

## 方案 A：英文说明移出数学环境（推荐修复本例）

保持英文和数学含义，将英文作为普通 Markdown，只把数学表达式放入 `$...$`。三个说明段落一起整理，避免第一、第二段在窄屏也成为长数学节点。

可审阅的完整示例：`prose-example.md`；使用现有 `compileMD` 编译出的验证 HTML：`prose-example.html`。这两个文件是方案产物，没有写回用户草稿。

结果：桌面与 375px 下目标段落、引用块均无横向溢出；英文按词自然换行。原有独立推导公式仍独立滚动。

代价：英文说明恢复正文的字体和字号，视觉上不再整段使用 KaTeX 的衬线字体。不能解决其他文章中真正不可分割的超长行内公式。

截图：`prose-desktop.jpg`、`prose-mobile.jpg`（临时方案效果，不代表代码已经修改）。

## 方案 B：含行内公式的引用段落局部横向滚动

临时实验规则：

```css
blockquote p:has(> .katex):not(:has(.katex-display)) {
  overflow-x: auto;
  overflow-y: hidden;
  padding-block: 6px;
  scrollbar-width: thin;
}
```

结果：两个视口下引用块 scrollWidth 均恢复为 clientWidth，内容在段落内部横向滚动。375px 下滚到末端时 `scrollLeft = 558.5`，整数 DOM 最大值为 558，差异来自子像素取整，末尾可达。

优点：原有文字、数学结构和字体保持完整；无需改文章源内容。

代价：长英文需要左右滚动；规则会把短行内公式所在段落也建立为滚动容器，6px 上下 padding 会改变段落高度。`overflow-y: hidden` 对高分式、上下限等仍需检查裁剪。当前实验仅覆盖本例，不应直接视为全站通过。

若选择正式实施，规则应放在 `PostContent.module.css` 并以 `.content :global(...)` 正确作用于构建期生成的 KaTeX 明文类。6px 仅沿用了已有独立公式的安全边距，不是已经定案的正文节奏调整。进一步收窄到“只含一个行内公式的段落”需要额外验证，不能把当前样例结果推广到混排段落、列表、callout 和历史对比。

截图：`scroll-desktop.jpg`、`scroll-mobile.jpg`（临时样式实验）。

## 不推荐的处理

- 只扩大引用背景：正文有 680px 阅读宽度限制，825px 内容在手机上依然无法容纳。
- 给引用块直接 `overflow: hidden`：消失的是内容，信息不可读。
- 全局强制 KaTeX `.base` 使用普通换行：介入数学内部排版，分式、矩阵、括号和对齐环境兼容性风险大。
- 全局缩小公式字号：文字会随内容长度变小，窄屏可读性差。
- 自动正则拆解 `\text{...}`：会涉及转义、嵌套花括号和数学/文字混排语义，本例不需要编译器改写。

## 推荐落地顺序与验证清单

1. 若仅修复截图：采用方案 A，修改草稿的三个说明段落，数学推导保持原样。
2. 若要额外容错：独立评审方案 B 或更精确的公式溢出容器，明确是否接受横向滚动与垂直节奏变化；不与正文语义修改混为一件事。
3. 实施时验证桌面/375/768、深浅主题、行内高分式与求和上下限、独立公式编号、列表/callout、历史版本比较。
4. 页面外围不得新增横向滚动，超长公式末端应可达，数学内容不能被裁掉，普通短公式的基线和段落间距保持正常。
5. 若改源码或构建器，运行项目对应 `npm run test:content`；纯样式变化优先做浏览器几何与截图检查。避免全量 build 重写用户现有生成资源。
