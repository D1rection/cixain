## 目标与授权

语言标记决定语法着色，不决定代码块是否具有统一背景、排版、复制按钮和行号规则。作者可以正常省略语言标记，无须逐篇补写 `plaintext`。

用户已授权创建 Trellis 任务并设计方案；当前仅规划，不修改实现、文章源文或生成产物，不启动实施。

## 已确认事实

- MNIST 碎片共有 7 个代码块：第一个标注 `plaintext`，其余 6 个未标注语言；线上 HTML 与本地生成 HTML 均呈现两种结构。
- 未标注语言的普通代码块被当前 Shiki 配置跳过；基础 `pre` 样式无背景色，行号仅匹配 Shiki 输出。
- `[!fold]` 内已有补纯文本语言的特殊处理，但普通正文没有。现行主题为明暗均使用 Everforest Dark。
- 现有行号约定：正文桌面端显示，≤768px 隐藏；折叠题干始终隐藏。
- `react:ComponentName` 为交互组件语法；数学公式与历史版本也共享正文编译链，必须纳入兼容性验收。

## 需求

1. 文章、碎片、静态页面以及共享编译器生成的历史正文采用同一普通代码块规则；覆盖 fenced code 和缩进代码。
2. 无语言、`text`、`plaintext` 的基础外观一致；受支持语言保留语法着色，不自动猜测语言。
3. 未知语言按纯文本展示，保留内容并采用统一外观；这是建议的容错行为，不新增构建错误。
4. 保留现有 Everforest 配色、字体、字号、内边距、圆角、横向滚动、复制交互和响应式行号策略。
5. 内容保真：保留缩进、内部空行、制表符、非断行空格和转义字符；复制不混入行号、按钮文字或 HTML 标记。采用当前 Shiki 的末尾换行处理约定。
6. 交互组件占位、KaTeX、行内代码、块引用 ID、目录以及搜索内容继续正确生成；编译异常仍应暴露。
7. 不要求修改既有 Markdown 或 frontmatter 日期，不新增运行时高亮及依赖。
8. 基础配色只作用于普通代码包装内的代码框，不改变交互组件自有样式、状态行为和历史交互代码框的配色。

## 验收标准

- [ ] MNIST 的 7 个代码块统一采用 Everforest 背景、文字颜色及普通代码块结构；桌面正文均显示行号，移动端均隐藏。
- [ ] 无语言、`text`、`plaintext`、未知语言、缩进代码及空代码块均得到统一结构；已知语言和别名仍有正确语法着色。
- [ ] 相同文本在不同语言标记下除语法着色外保持相同几何排版；明暗主题切换不改变尺寸。
- [ ] 普通正文、引用、callout 和 fold 遵守同一语言规则；fold 保留现有局部间距与隐藏行号规则，标题不进入 TOC。
- [ ] 超长行只使代码块横向滚动，页面不横向溢出；复制结果与代码正文一致，排除装饰。
