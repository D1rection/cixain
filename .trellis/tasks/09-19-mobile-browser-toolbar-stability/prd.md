# 移动端滚动时保持 Android Chrome 工具栏展开

## 背景与目标
用户所说的导航栏是 Android Chrome 自带的地址栏／工具栏，不是网站 NavBar。希望阅读博客时上下滑动正文不触发浏览器工具栏收起、展开及其动画，减少阅读区域变化。用户已确认研究独立滚动容器方向，并授权创建 Trellis 设计方案；本轮不进入实现。

## 范围
- 适用于现有移动端断点（宽度 ≤768px），首要验收平台为 Android Chrome 普通浏览模式。
- 长文章、首页、归档、文章索引、分类／标签／系列、关于及错误页均可完整访问。
- 网站 NavBar 外观和既有 sticky 行为保持一致；正文、页脚、背景和菜单视觉不重设计。
- 阅读进度、回到顶部、目录高亮、目录跳转、跨文章块引用、图片懒加载、搜索和图片预览正常工作。
- 桌面端保持页面滚动体验；SSG 首屏、客户端导航及打印完整性不退化。

## 非目标
- 不提供跨浏览器的强制工具栏控制 API，不承诺 Safari 或所有未来 Chrome 版本。
- 不要求把用户已经主动收起的工具栏强制展开；核心场景为工具栏展开状态打开页面后阅读。
- 不改成 PWA／全屏模式，不禁止用户缩放，不用全局 touchmove preventDefault 模拟滚动。
- 不新增浏览器前进后退位置恢复体系，不改变现有 pathname 切换回顶、带 hash 跳转优先策略。

## 验收标准
1. 在记录了 Android 版本、Chrome 版本及工具栏位置设置的真机上，从工具栏展开状态打开长文，上下滑动、惯性滚动、到顶／到底继续拖动时，浏览器工具栏保持展开，无收缩动画。
2. 短页面不产生意外页面滚动；长页面可到达全部内容及 Footer，无双重纵向滚动、横向页面溢出或裁切。
3. 网站导航保持原来的吸顶与菜单交互，48px／52px 两个高度断点均无错位。
4. 进度条、回顶按钮、目录高亮随正文滚动更新；目录和跨文章块引用定位正确。
5. 普通路由切换回顶；带 hash 时保留定位；搜索／主题切换不误触回顶。前进后退不残留浮层或锁定。
6. 搜索和图片预览期间正文不滑动；关闭后位置保留，搜索键盘打开后输入及结果可达。
7. 横竖屏及跨越 768px 断点后没有白屏、双滚动或失效的监听；保留合理的阅读位置。
8. 桌面端、SSG 水合、打印完整长文、代码／公式／表格横向滚动及基本键盘访问正常。
9. 真机验收未完成时只能标记“功能实现／自动验证完成，浏览器工具栏行为待验”，不能宣称目标已达成。

## 已知体验变化
独立容器阻断纵向滚动链后，正文区域的原生下拉刷新可能不可用；此项属于方案预期取舍，验证时明确记录。

## 状态
in_progress。已按用户确认的设计开始实现；Android Chrome 真机工具栏行为仍待在目标设备上验收。
