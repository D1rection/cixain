# Navbar 脱离滚动容器以消除滚动条占位空隙

## 目标

在使用经典竖直滚动条的浏览器中，网站 Navbar 仍然铺满整个视口宽度，不因正文滚动容器的滚动条 gutter 在右侧留下空隙。保留上一任务建立的移动端独立滚动容器，以继续规避页面根滚动触发移动浏览器工具栏变化。

## 需求

- 将网站 `NavBar` 从 `ScrollContainer` 内移到 `#root` 的独立布局层；`Layout + Footer` 继续作为滚动容器内容。
- Navbar 在移动端和桌面端均占满可用视口宽度；桌面端仍可正常页面滚动，移动端正文继续由 `ScrollContainer` 滚动。
- 保持 Navbar 的主题、菜单、搜索、背景切换、路由激活态和 48px/52px 响应式高度行为不变。
- `ScrollToTop`、阅读进度、目录高亮、回顶按钮、搜索和图片预览继续使用上一任务的统一滚动目标。
- 不通过隐藏滚动条解决问题，不使用固定 8px/系统滚动条宽度补偿，不改变用户的滚动可访问性。
- 打印、SSG 水合、直接打开文章、SPA 路由切换和前进后退不回归。

## 非目标

- 不重新设计网站 Navbar 的视觉样式。
- 不保证浏览器原生滚动条本身消失；滚动条仍属于正文滚动容器。
- 不改变浏览器地址栏／工具栏是否收起的控制策略；这仍以独立滚动容器为基础。

## 验收标准

1. 使用经典滚动条的浏览器中，Navbar 背景从视口左边缘铺满到右边缘，不出现滚动条宽度的背景空隙。
2. 使用 overlay 滚动条的 Chrome 移动端中，Navbar 与正文滚动行为保持上一版本一致。
3. 移动端长文章可以滚到 Footer；滚动条仅属于正文容器，`document` 仍不发生页面滚动。
4. Navbar 菜单展开层、搜索按钮、主题切换和路由跳转均可用；菜单层不被滚动容器裁切。
5. 桌面端文章、首页双栏、宽屏目录、横向代码／公式／表格滚动均正常。
6. `npm run build`、SSG 输出、打印样式和基本运行时检查通过。
