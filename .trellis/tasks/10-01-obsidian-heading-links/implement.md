1. 为两处真实失败写法补隔离回归夹具，同时断言 href 与目标 HTML ID 一致，不能只断言校验放行。补普通 URL 与 wiki 同 hash 不同语义的用例。
2. 拆分 Markdown 的 prepare/finalize，保留 compileMD 包装器与插件顺序。先以现有夹具验证 html、anchors、interactive、公式、代码块与块 ID 没有无关变化。
3. 加入源标题元数据与 wiki 原始节点关联，恢复被插件替换丢失的位置；在块/标题最终 ID 生成后建立文档索引。覆盖格式、公式、块 ID 标题和折叠题干排除。
4. 实现统一解析器与歧义规则，在 finalize 修改关联 href。普通 URL 单独收集；校验消费同一 resolvedAnchor；保留 raw/position 并消除二次收集。
5. buildPosts 统一准备可见内容树、建立全量索引，再解析和校验。校验通过后才序列化/写出所有 HTML/JSON 与 anchor-index.json；新增中间文件加入 .gitignore。
6. build-history 读取本次索引，历史 wiki 使用当前内容规范 URL；更新 compilerVersion，验证索引缺失/版本错误/旧标题失效的策略。当前正文同文链接仍使用局部 hash。
7. 更新 content-validation、content-pipeline 与 writing-fragments 的标题链接说明；明确“文件名不按文章 title 猜测”和“章节标题可以解析”的区别，移除要求作者手写标题 ID 的示例。
8. 完成下列检查并审阅全范围差异。保持用户现有未提交修改；提交按 Trellis 的独立确认流程进行，不包含本轮未授权的提交/推送。
