# 移动端标签与系列浏览入口

## Goal

在不增加移动端展开菜单一级入口数量的前提下，让读者能从任意页面稳定发现并访问全部分类、系列和标签。

## Requirements

- 移动端（`<=768px`）展开菜单始终保持 6 个一级入口：`首页 / 归档 / 浏览 / 关于 / 搜索 / 外观`。
- 新增「浏览」入口，替换移动端菜单中的 GitHub 入口；桌面端导航中的 GitHub 保持不变，移动端仍可从「关于」页访问 GitHub。
- 新增可直接访问、后退、收藏和分享的 `/browse/` 页面，集中展示：
  - 分类：使用 `SITE.categories` 的配置顺序并显示文章数；
  - 系列：按系列内最近文章日期降序并显示篇数；
  - 标签：按文章数降序，同数量按稳定名称顺序排列，并显示篇数。
- 浏览页的数据必须由当前已发布文章元数据动态派生，不维护第二份手写分类、系列或标签清单。
- 浏览页中的条目继续链接到现有 `/category/:slug/`、`/series/:slug/`、`/tag/:slug/` 页面；不改变筛选页及系列内文章排序规则。
- 移动端菜单保留现有视觉语言，但 6 个入口应使用等宽布局、图标和短文字标签；「主题」切换的可见名称改为「外观」，避免与内容主题混淆。
- 新增页面必须进入现有静态生成、canonical/meta 和 sitemap 流程，保证 GitHub Pages 目录型 URL 可直接打开。
- 桌面端现有导航、首页侧栏及内容能力保持不变。
- 不引入新依赖，不修改文章内容或 frontmatter。

## Non-goals

- 不重做全站导航体系或改成常驻底部导航。
- 不在本任务中增加标签搜索、筛选、折叠或个性化推荐。
- 不改变标签页、系列页、分类页的文章卡片和分页行为。
- 不删除 GitHub、背景或主题切换能力。

## Acceptance Criteria

- [x] 在 320px、375px、768px 视口下，菜单展开后恰好显示 6 个一级入口，无横向溢出或文字截断。
- [x] 移动端 6 个入口依次为首页、归档、浏览、关于、搜索、外观；GitHub 不占用移动端一级入口。
- [x] 从任意移动端路由经「菜单 → 浏览」可到达 `/browse/`，并能进入每一个现有分类、系列和标签页面。
- [x] `/browse/` 显示正确的分类、系列、标签及计数，排序与桌面侧栏的既有规则一致。
- [x] 浏览页标签触控区域不小于 44px 高；系列和分类条目同样适合触控操作。
- [x] 菜单按钮正确暴露展开状态和受控区域；键盘可用 Enter/Space 打开，Escape 可关闭；导航后菜单关闭。
- [x] 当前页面入口有可感知的激活状态；浏览页及其下属分类/系列/标签页能正确体现内容浏览语境。
- [x] 769px 及以上的桌面导航和首页侧栏视觉、入口及数据不发生回归。
- [x] `/browse/` 生成静态 HTML、正确 canonical/meta，并出现在 sitemap 中。
- [x] 生产构建通过，移动端首页、浏览页、代表性标签页和系列页无控制台错误。

验证备注：已完成生产构建、静态 HTML/meta/canonical/sitemap 检查、taxonomy 统计断言及浏览页路由回归；当前自动化浏览器接口不支持强制指定视口，因此 320/375/768px 的入口数量由响应式 CSS 断点与固定六列布局进行代码级核验。

## Notes

- 当前生产数据为 17 篇文章、3 个系列、11 个标签，适合在浏览页完整展示，无需“查看更多”。
- 若未来标签数量超过约 24 个，再单独评估标签过滤或折叠；不提前扩展本任务范围。
