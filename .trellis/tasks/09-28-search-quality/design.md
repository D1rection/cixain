# 设计：完整内容、分段召回、明确排序

## 选择
保留现有 Fuse 依赖作为有限的模糊补充；主召回先采用可测试的精确子串/关键词匹配。当前规模无需新增搜索引擎、中文分词依赖或远端服务。完整正文存储为分段纯文本，避免把整篇长文交给默认位置敏感的模糊匹配。

## 构建契约
复用任务 1 的已发布注册表、URL 和编译后标题锚点，产物结构：
`{schemaVersion, documents:[{id,kind,url,title,tags,description,sections:[{anchor,heading,text}]}]}`。
所有正文都进入 sections；按标题分段，超长段按段落切分并保留相同最近标题锚点；没有标题的开头 anchor 为 null。数据不包含正文 HTML/历史版本。

从 Markdown AST 提取可读文本，代码保留内容、公式只保留一份 TeX，链接保留显示文字；忽略 frontmatter、块标记、纯图片地址及交互组件源码/配置。交互组件旁的自然语言说明可检索。显式 raw HTML 如实际存在，需使用解析器取可见文字而非正则剥标签。抽取发生在链接解析后、代码高亮和公式渲染前；不污染页面 HTML。默认摘要可共享同一纯文本抽取能力。

输出仅由本次发布清单产生。开发与生产显式传入 mode，不能依赖上次残留 posts.json；构建时校验 schema、重复 ID、相对本站 url。生成到 public 后复制到 dist 的顺序保持清楚，避免 Vite 打包旧索引。

## 查询与排序
标准化大小写和 Unicode，保留原文与映射供高亮，保留 C++/函数名等符号。中文连续输入按子串查找；空格分开的词采用 AND，允许分别出现在文档不同字段/段落。中文不引入自动分词。先找全部精确命中，再以 Fuse 对标题/标签补少量英文错字候选；短中文和超长查询不强行模糊。

排序按可解释的分层：标题完全相等 → 标题含完整查询 → 标题/标签覆盖全部词 → 摘要/标题段命中 → 正文命中 → 模糊候选。层内按词覆盖、标题位置和文档 ID 稳定排序；日期不能盖过相关性。同一 document 去重，展示最相关段落。

上下文从命中窗口截取，保留前后文字；多词跨段时显示最佳段并可说明其他命中。高亮用 React 文本片段和 mark，禁止将查询拼入 HTML。标准化后的范围必须映射回原文，避免全角等变换导致错位。

## 浮层与导航
复用 SearchOverlay，扩大上下文展示而不改整体导航。使用明确状态机 idle/loading/ready/error；成功索引在同页会话缓存，失败清除缓存后可重试。useEffect 清理过期请求/焦点定时器；防止旧查询结果覆盖新查询。输入法 composition 期间不处理 Enter 选择。

使用语义化 dialog 与有标签输入，焦点锁定及恢复；可通过 listbox/active descendant 管理结果键盘，具体 ARIA 组合实施时核对。提供可见关闭/重试/更多结果按钮；移动键盘下结果区仍可滚动。

结果使用注册表 url 加可选 anchor，选择结果沿用任务 1 确立的可靠导航（默认规范 a href 完整加载 SSG），避免依赖当前页 Context 是否包含目标元信息；支持新标签打开。

## 性能和备选
索引仅打开搜索时加载，按需构建内存检索结构。记录压缩前后字节、首次加载/解析与查询 p50/p95；以当前真实内容及 10 倍合成语料测量，目标桌面暖查询 p95 <100ms，明确设备和样本。若实测主线程卡顿或传输过大，再决定 Worker/静态分片/专门倒排引擎；不在未测量前加入架构复杂度。

## 回滚
独立于 fragment 提交；保留任务 1 的类型与 url 能力。若新 schema 回滚，生成器和消费者必须一起回滚，不能混搭。
