# 修订对比改进设计

## 决策与边界

沿用构建期产生差异、前端按需获取静态 JSON 的架构。用一项任务统一推进“对齐 → 保真渲染 → 分组与导航”，因为三者共享变更区域契约，分开交付容易产生计数和正文不一致。

## 1. 结构化比较

把编译后的 HTML 解析为结构树，以顶层内容节点建块，覆盖段落、标题、列表、引用、代码、表格、图片及顶层公式；不再用标签正则作为结构解析器。优先复用 unified 生态和现有依赖，实施时查询库文档后确定解析入口，必要时显式声明直接依赖。

每块保存原始结构、语义类型、语义指纹、文本匹配投影和当前侧定位信息。指纹包含 href、图片 data-src/src、公式 TeX、代码内容、强调结构等有意义属性；忽略复制按钮和生成性装饰，但保留原始节点用于渲染。只改链接地址或图片地址也应产生变更。

先以唯一且完全相同的语义块作为有序锚点，在锚点间使用序列对齐。禁止固定 4 块前瞻；重复“待续”等低信息块不能独立成为强锚点。只在同类型、同章节候选区域内配对相似修改，未达到可信度则保持整块删除/新增。标题配对可忽略章节编号作为匹配投影，但编号变化仍呈现为差异。

限制区间对齐计算量；超过预算时保留已确定锚点，并将剩余区间按完整结构删除/新增，保证不丢内容、不破坏公式。记录耗时与最大样本表现后确定常量，不为缩短时间静默漏变更。

## 2. 保留富文本的行内差异

以文本叶节点和不可拆分的语义节点比较，渲染回 HTML 树。英文按词、中文按字素；空白和标点保留。KaTeX 以一条规范化公式源作为比较键，完整渲染树作为原子载荷，绝不把 MathML/annotation/视觉文本一起抽成可见文字。

链接保留目标和属性，强调保留标签；行内代码按原子处理。复杂或结构不兼容的修改降级为旧/新完整块，并放在同一变更区域。修改公式显示旧/新完整公式及局部红绿背景，不在公式上打删除线。图片、代码、表格同理。普通文本删除线只施加在文本标记上，不施加于可能包住数学和代码的祖先。

## 3. 变更区域与视觉

未改动正文沿用原有排版；小改动仅在文字上红删绿增，不新增整段卡片。相邻同类新增/删除块合为一个区域并仅提示一次；章节边界、未改动块切断合并。配对替换区域按“原文 → 修订后”上下排列，共用区域定位，避免旧新文本穿插到别的章节。新插入的一整节使用一个连续绿色区域，内部保留标题和段落节奏。

沿用暖色正文、站点字体与 rhythm 间距 token。新增区域用绿色浅底、左侧竖线和“+ 新增”；删除用红色及“− 删除”。行内文字继续下划线/删除线，开头提供一份简短图例。标签从逐段重复改为组级提示；修正标签之后首个内容块的上边距，避免大面积空白。明暗主题分别调差异色变量，实际正文可读性必须用截图复核。

修订状态行布局：比较日期方向 · N 处变更 · 上一处 / 下一处 · 回到当前。窄屏自然换行，不做横向工具栏。导航依据区域 ID，首尾禁用；点击后将焦点和滚动位置移至区域入口，播报“第 i / N 处”，不在页面滚动时频繁播报。减少动画偏好下立即定位。

## 4. 数据与兼容

`createRevisionDiff` 返回 html、changes、changeCount；changes 为按阅读顺序的 `{ id, type }[]`，type 为 added/removed/modified。changeCount 明确定义为 changes.length，一个旧新替换组算一处。正文同区域挂唯一 `revision-change-N` ID，前端导航直接使用此清单，不再自行数 DOM。

当前侧标题保留唯一定位，删除侧标题及被复制的内部 ID 使用旧侧前缀，并同步内部引用；TOC 只来自当前侧标题，不能依赖比较后的混合文本或位置推测。构建时核对 TOC 每一项确实有唯一目标。

更新 diff/compiler 版本及 JSON schema 版本，generation 继续包含 compiler 版本，生成全量新资源；前端校验 schema/generation/目标正文一致性。compare 参数和历史提交 ID 不变。整站同批发布，资源不匹配时回退当前文章并显示可重试提示。

## 5. 风险与回退

结构比较的主要风险是语义归一化过度、错误相似配对和锚点 ID 冲突，分别用属性变化测试、长插入/重复段测试及目录完整性断言防护。维持现有历史交互组件惰性代码展示及 HTML 安全过滤。

构建或验收失败不发布新产物。发布后若需回滚，回退本任务代码及对应整站构建，不单独回退 JSON 或 CSS，避免代际混用。
